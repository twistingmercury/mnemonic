# Glossary

> Back to [Design Index](../README.md)

Definitions of key terms used throughout the Mnemonic documentation. Terms are listed alphabetically.

---

<a id="agent"></a>**Agent**
A Claude Code agent role (e.g., `go-engineer`, `devops-engineer`). Associating patterns with agents by relevance score is **planned, not implemented**: the `db/` component defines agent tables (`agents`, `pattern_agent_associations`) and an `Agent` graph constraint, but no Mnemonic service has agent code, the pattern API has no agent field, and search has no agent filter.
See also: [Pattern](#pattern), [Knowledge Graph](#knowledge-graph)

<a id="chunk"></a>**Chunk**
A decorated section of a pattern file that is independently vectorized and indexed for semantic search. The API creates chunks when a pattern is created or updated, by splitting the content at headings (any level) marked with the `[//]: pattern` decorator; a chunk runs to the next decorator or end of file. Content with no decorated section becomes one chunk holding the whole content, titled by its first heading or `Content`. Each chunk has its own enrichment status and gets its own embedding, stored in the `pattern_chunks` database table.
See also: [Decorator](#decorator), [Embedding](#embedding), [Pattern File](#pattern-file)

<a id="concept"></a>**Concept**
A key idea extracted from a pattern's full content by OpenAI (`gpt-4o-mini`) during enrichment, stored as a `Concept` node in Neo4j and linked to the pattern by `MENTIONED_IN`. Patterns that share concepts are linked by `RELATED_TO`.
See also: [Enrichment](#enrichment), [Knowledge Graph](#knowledge-graph)

<a id="cosine-similarity"></a>**Cosine Similarity**
A measure of similarity between two vectors, calculated as the cosine of the angle between them. Values range from 0.0 (orthogonal/unrelated) to 1.0 (identical direction). PGVector's `<=>` operator returns cosine *distance*; Mnemonic computes similarity as `1 - (embedding <=> query)`.
See also: [Embedding](#embedding), [PGVector](#pgvector)

<a id="decorator"></a>**Decorator**
The exact line `[//]: pattern` placed before a heading in a pattern file (blank lines in between are allowed). Decorators mark sections for chunking and vectorization. Content before the first decorator is not indexed (unless the pattern has no non-empty decorated section, in which case the whole content is one chunk); undecorated headings after a decorated section are absorbed into that section's chunk. By convention the `## Overview` section is not decorated and comes first.
See also: [Chunk](#chunk), [Pattern File](#pattern-file)

<a id="embedding"></a>**Embedding**
A numeric vector (array of 2000 floating-point numbers) that represents the semantic meaning of text. Generated by OpenAI's `text-embedding-3-large` model with Matryoshka truncation to 2000 dimensions. Similar texts produce similar embeddings, enabling semantic search via cosine similarity.
See also: [Cosine Similarity](#cosine-similarity), [Enrichment](#enrichment), [PGVector](#pgvector)

<a id="enrichment"></a>**Enrichment**
The asynchronous pipeline that transforms a raw pattern into a searchable, interconnected knowledge entry. The API validates and stores the pattern, its chunks, and one enrichment job per chunk, then publishes the jobs to RabbitMQ (`enrichment-jobs`). The enricher (1) embeds each chunk via OpenAI, (2) once every chunk is embedded, extracts concepts from the full content via OpenAI (`gpt-4o-mini`), (3) syncs `Concept` nodes and `RELATED_TO` edges in Neo4j, and (4) marks the pattern `enriched`. Patterns and chunks track status as `pending`, `enriched`, or `failed`; failed jobs are retried by the enricher's retry sweep. Only `enriched` chunks appear in search results.
See also: [Chunk](#chunk), [Embedding](#embedding), [Knowledge Graph](#knowledge-graph)

<a id="enrichment-job"></a>**Enrichment Job**
A row in the `enrichment_jobs` table, one per chunk, created by the API in the same transaction as the chunk. Its ID is published to the RabbitMQ `enrichment-jobs` queue (with W3C trace context in the message headers). The enricher claims it, and a failed job is rescheduled after `enrichment.retry_delay` (default 30s) until it reaches its attempt limit. Job states are `pending`, `processing`, `completed`, and `failed`; completed and failed jobs are deleted after their retention period.
See also: [Enrichment](#enrichment), [Chunk](#chunk)

<a id="frontmatter"></a>**Frontmatter**
The YAML metadata block at the top of a pattern file, delimited by `---`. Its fields map to the API's create request: required `name`, `entity_type`, `language`, `domain`; optional `description` (required by the mnemonic-patterns validator), `tags`, `version`, `related_patterns`. The file body becomes `content`. See the [Pattern File Schema](pattern-schema.md) for the full specification.
See also: [Pattern File](#pattern-file)

<a id="hnsw"></a>**HNSW**
Hierarchical Navigable Small World. A vector index algorithm used by PGVector for approximate nearest-neighbor search on chunk embeddings. Chosen over IVFFlat for chunk-level search because it provides better recall without requiring periodic retraining. The index itself is defined in the `db/` migrations.
See also: [IVFFlat](#ivfflat), [PGVector](#pgvector), [Chunk](#chunk)

<a id="ivfflat"></a>**IVFFlat**
Inverted File with Flat compression. A vector index algorithm that partitions embeddings into clusters via k-means, then searches only the nearest clusters at query time. Previously used for pattern-level embeddings; now deprecated in favor of HNSW on chunks.
See also: [HNSW](#hnsw), [PGVector](#pgvector)

<a id="knowledge-graph"></a>**Knowledge Graph**
The combination of Neo4j graph relationships and PostgreSQL vector data that represents the semantic structure of the pattern library. The enricher writes `Pattern` and `Concept` nodes, `(Concept)-[:MENTIONED_IN]->(Pattern)` for each extracted concept, and `(Pattern)-[:RELATED_TO {similarity}]->(Pattern)` when two patterns' concept overlap (shared concepts divided by the larger concept count) is at least 0.3. `find_related_patterns`, `get_pattern`, and the graph expansion in `search_patterns` read these edges. `Agent` nodes and `RELEVANT_FOR` edges are planned, not implemented.
See also: [Agent](#agent), [Pattern](#pattern), [Enrichment](#enrichment)

<a id="mcp-model-context-protocol"></a>**MCP (Model Context Protocol)**
The protocol Claude Code uses to communicate with external tool servers. Mnemonic exposes three read-only MCP tools (`search_patterns`, `find_related_patterns`, `get_pattern`) via Streamable HTTP at `/mcp` on port 8081, served by the mcp service, which has no authentication of its own (the gateway handles it). Claude Code discovers and invokes these tools automatically during conversation.
See also: [Streamable HTTP](#streamable-http)

<a id="pattern"></a>**Pattern**
A Markdown document with YAML frontmatter that captures a piece of team knowledge -- a coding convention, architectural decision, best practice, or design pattern. Patterns are the core unit of knowledge in Mnemonic. They are stored in PostgreSQL, chunked and vectorized for semantic search, and projected into Neo4j (as `Pattern` nodes linked to extracted concepts) for graph traversal.
See also: [Pattern File](#pattern-file), [Chunk](#chunk), [Enrichment](#enrichment)

<a id="pattern-file"></a>**Pattern File**
The on-disk Markdown format for patterns. Consists of YAML frontmatter followed by an `## Overview` section (undecorated, so not indexed) and one or more decorated sections (indexed as chunks). Validated by `install/validate.sh` in mnemonic-patterns before loading, and by the API on create and update. See the [Pattern File Schema](pattern-schema.md) for the full specification.
See also: [Frontmatter](#frontmatter), [Decorator](#decorator), [Chunk](#chunk)

<a id="pgvector"></a>**PGVector**
A PostgreSQL extension that adds vector data types and similarity search operators. Mnemonic uses PGVector to store embeddings as `vector(2000)` columns and to perform cosine similarity searches using the `<=>` (cosine distance) operator with an HNSW index on `pattern_chunks`.
See also: [Embedding](#embedding), [HNSW](#hnsw), [Cosine Similarity](#cosine-similarity)

<a id="streamable-http"></a>**Streamable HTTP**
The MCP transport protocol used by Mnemonic. Claude Code connects to `http://localhost:8081/mcp` (`claude mcp add --transport http mnemonic http://localhost:8081/mcp`) and sends JSON-RPC 2.0 messages over HTTP POST. Mnemonic runs in stateless mode (no session persistence), and the HTTP handler continues any incoming W3C trace context.
See also: [MCP (Model Context Protocol)](#mcp-model-context-protocol)
